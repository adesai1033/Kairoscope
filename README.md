# kairoscope

> Your video agent is watching every frame. It doesn't need to.

**kairoscope** makes AI video agents faster and cheaper. It decides which frames, at
what resolution, a vision model actually needs to see, and finds key moments without
watching the whole video.

*Kairos* is the Greek word for the right moment.

## Why

For a video agent, the two numbers that matter are **model calls** and **dollars per
answer**. A model call takes seconds; local frame work takes milliseconds. So the way
to win is to make fewer and smaller model calls — not to watch every frame.

kairoscope does this by searching instead of scanning, and by **measuring** what each
task needs instead of guessing:

- **`find_event`** finds the moment something happens by bisection: a judge model looks
  at a small strip of frames around a midpoint and answers yes/no, narrowing the window
  exponentially. Noisy judges are handled with optional voting and a verify-and-repair
  pass (on by default) that re-checks the boundary and fixes wrong turns.
- **`calibrate`** takes reference answers at full quality, then tries progressively
  cheaper sampling configs (fps, resolution, crop, dedupe) and returns the cheapest
  `Profile` whose answers still agree with the reference (default 95%). Dense low-res
  frames often beat sparse high-res frames at equal token budgets — but some tasks are
  resolution-sensitive, so kairoscope measures rather than assumes.
- **`Video`** keeps the container open, seeks to keyframes, decodes only the frames you
  ask for at the size you ask for, and caches them with bounded memory.
- **`CostLedger`** records every call — images, dimensions, tokens, latency, estimated
  dollars — so cost is a number you read, not a surprise on an invoice.

What *doesn't* help: greyscale and JPEG compression. Hosted APIs price images by pixel
dimensions, so the real levers are frame count, resolution, cropping, and dedupe.

## Install

```bash
pip install "kairoscope[claude]"   # or: pip install kairoscope (core only)
```

Core dependencies are just `av`, `numpy`, and `pillow`; provider SDKs are optional
extras. Python ≥ 3.12.

## Quickstart

```python
import kairoscope as ks
from kairoscope.judges.claude import ClaudeJudge

video = ks.Video("game.mp4")
judge = ClaudeJudge()  # default model: claude-sonnet-5-5
result = ks.find_event(video, judge)  # judge prompt: "Has the ball left the shooter's hands?"
print(result.seconds, result.calls, result.cost.dollars)
```

## How `find_event` stays reliable

A single still can't tell a dribble from a shot, and models are most confused right at
the event boundary. kairoscope's answers:

- **Context strips:** the judge sees ~5 frames around each midpoint (±0.2 s), tiled in
  time order with relative time labels and the judged frame outlined in red.
- **Verify-and-repair:** after bisection converges, the boundary is re-checked with
  early-stopping majority votes; a failed check walks outward by doubling steps and
  re-bisects. In prototype simulations this took plain bisection from unreliable to
  near-perfect within ±3 frames for a handful of extra calls.

## Development

```bash
uv sync --all-extras       # install core + claude + dev
uv run ruff format .
uv run ruff check . --fix
uv run mypy src --strict
uv run pytest -q           # offline suite; never calls real APIs
```

Tests use synthetic clips generated at runtime and a seeded `SimulatedJudge`, so the
default suite is fast, free, and deterministic. Live API tests exist behind
`uv run pytest --live -m live` (costs money, needs `ANTHROPIC_API_KEY`).
